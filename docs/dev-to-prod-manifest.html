Four surfaces are forked between the trees, and all four have to move together: the page trees (pages/<page>/{prod,dev}), the component library (components/ vs components-dev/), the Redux slices (features/xSlice vs features/dev/devXSlice), and the store registration (store/pageReducers.ts vs store/devReducers.ts). Shared modules — api/, utils/, hooks/, constants/, interfaces/ — are single-copy and already compiled into prod; section 5 confirms which of them simply become reachable.

What the tooling already does. node scripts/promote-page.mjs <page> writes the dev tree over prod with the swaps applied, trashes prod-only files, rewrites the matching slice, and copies new library files. It stops on changed library files unless you pass --lib. Section 6 lists what it cannot do, and the two pages it currently crashes on.

One breaking change in here

mobile/MobilePerfHeader.tsx renames its prop from info={X_INFO} to helpPage="x". Seven prod files still pass the old one, so the component and Coupons, Orders, Receivers and Cashiers must land in the same commit. Cashiers is the awkward one: its dev tree dropped the component during the mobile rebuild, so there is no dev file to swap in — promoting the component forces cashiers along with it.

The Shared-groups pickers now go too. storePicker/SearchType and storePicker/SelectGroup add a “Shared” option that prod had no concept of — which is why they were held back. User Management ships Shared Groups, and the shared_groups/ endpoint is already on the prod API, so they move with it. components/UserDataLoader.tsx:184 also gates restoring a saved shared group on apiEnv === "dev"; that gate is outside every page tree, so check:split never sees it and it has to be removed by hand.
The scanner rides with Item Lookup. scanner/ScannerView.tsx is a 139-line change, and scanner/confirmRead.ts, scanner/useScanGun.ts and scanner/scannerView.css are new — the confirmed-read fix and scan-gun support. pages/lookup/dev and shared/itemPerf/dev both import them, so Item Lookup cannot be promoted without taking the scanner work with it. That work was last noted as awaiting a device test.

6 · What promote:page will not do

  • Create the two missing slices and register them in store/pageReducers.ts (Sales, Tickets) — it crashes without them.
  • Coming Soon release for the four new pages: remove each entry from COMING_SOON_CATEGORY in components/navigation/utils.tsx and restore userLevels: ["*"].
  • Add Sales Tracker and Tickets to the flat nav list at the top of the same file — the one feeding the Settings nav editor. Item Actions and both Price Opt entries are already there.
  • Delete the dev-API gate in each new page's switcher (pages/<page>/<Name>.tsx), which returns DevOnlyNotice unless apiEnv === "dev" and the URL is really DEV_API_URL. Price Opt has two switchers, not one.
  • Decide on App.tsx:152 — ReportIssueModal is gated on apiEnv === "dev", outside any page tree, so check:split never sees it.
  • Sales Tracker's flag — useTrackerEndpoint is gated to the dev API. Once subs/sales_tracker is on prod, drop the flag and the fetchSubSales fallback.
  • UPC List — promoting hooks/useUpcDevCtx.ts flips fixes from false to true. A product decision, not a merge.
