Getting started

Three steps to a file

  1. Pick a store and a date range

    Same search card as everywhere else. Press Load config. This reads the range once and fills the whole page: the stores it covers, the values your filters can hold, every column of the line, and two hundred sample rows.

  2. Shape the file on the left

    Tick what you want in it. The panel on the right redraws as you go, so what is on screen is what the file will hold — same columns, same order.

  3. Press Build export

    The file is written straight to storage and you get a download link. Nothing downloads into the browser, so size is a wait rather than a problem.

Nothing you tick costs a round trip. The sample redraws from the rows already in hand. Only the first search and the build itself talk to the server.
Shaping the file

The configuration column

Every section is shut until you open it, and the line on the right of each one is the answer — so the column reads as a list of decisions already made.

Stores, Days, Sale Types, Ring Types, Sub Departments, Vendors, Cashiers, Price Types

Tick what to keep. Each list holds only what this range actually contains, so nothing you can pick comes back empty. Untick nothing and the whole list is included.

Products

Paste or type product codes, and words to find in the description. A description word is a contains-match — MILK finds WHOLE MILK GAL. Fill both and a line has to match a code and a word.

Columns

Which columns the file holds, and in what order — drag a heading on the preview to move one. Personal columns (customer name, contact, location) are marked and can be turned on or off together.

Group By and Aggregates

These two make the file a summary instead of the lines. Group By is what each row is; Aggregates are the numbers worked out for it. Set one and the file changes shape — the panel says which shape it currently is at the top.

Output

File name, format, how dates are spelled, whether voids and refunds are included, and what the file is sorted by.

Unticking everything in a list is not a filter. The export reads an empty list as "no filter at all", so the file would hold every one of them. Build export stops and says which list to fix.
The query box

Your configuration, written out

The box above the preview is not a separate thing to keep in step — it is the configuration, written as a query. Tick a vendor on the left and a line appears in its where. Group by something and it becomes a rollup.

You can also go the other way. Edit the text and press Apply to configuration, and the panel on the left changes to match. Anything the configuration cannot hold is listed underneath rather than dropped quietly — a filter on a column the export has no setting for, for instance.

While the text matches your configuration there is nothing to apply, and the button says so. As soon as you type, the box is yours until you apply it or press Discard edits — and the preview below still shows the configuration, not your half-finished text.

It runs nowhere. Nothing typed in that box is sent anywhere. The file is always built by the server from the configuration, from values it checks.
Building it

What happens when you press Build

The strip at the bottom is the summary of what is about to be built: how many stores, what shape, and every filter that is actually narrowing something. If the Build button is off, the reason is under it.

When it finishes you get the file, its size and row count, and a link that lasts an hour. Back to configuring puts the panel back without losing the file — it is in Previous builds either way.

A long export can look like an error. The connection stops waiting after 150 seconds, and the browser reports that as a failure even though the file is usually still being written. If that happens, look in Previous builds a minute later before trying again.
Saving and coming back

Configurations, queries and past builds

Saved configurations — the Saved button

A named set of choices you can load again. It holds no dates on purpose: the report is the report, whether you run it for September or October. Load one onto any range.

Saved queries — Queries in the query box

The text of a query, kept under a name and description. Opening one loads it — the panel on the left changes to match, and anything the configuration cannot hold is listed. Useful for the ones you write by hand.

Previous builds

Every file you have built, newest first, grouped by the configuration it came from. Each one carries its file name, what it covered, and the query it ran.

Reload puts a past build's settings back on the panel — from the build itself, so it is exactly what produced that file even if the configuration has changed since. It leaves your dates alone, so you can run last month's question against this month. Label attaches a configuration to a build you ran ad-hoc. Delete removes the file and its record.

Links expire, and a delete is permanent. Download links last an hour and are made fresh each time the list is opened — so an old one stops working, but the file is still there. Deleting a build cannot be undone.
Worth knowing

Three things that surprise people

These numbers are not the sales reports'

This is an extract of the raw lines — tender rows, voids, department transfers and untendered modifications are all in there, and refunds are stored positive. A store total from here runs roughly double what the sales pages say for the same window. That is the nature of the data, not an error.

The preview is a sample, not the file

Two hundred rows taken wherever the scan landed — often a handful of stores and a couple of sale types. The columns are the file's; the rows are an illustration. A summary's numbers on screen are that sample's, not the range's, and the preview says so.

Price type words belong to the company

One company says Regular and Managers Special, another says REG and STOR. The list you see is what these stores use. Load a configuration saved for a different company and the page tells you which of its price types do not exist here.
