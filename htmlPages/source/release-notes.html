The Client Help Desk, rebuilt

Coming Soon · owners and up · dev mode, desktop

The old page was a mock that predated the ticket tables by about five months. It now runs on the real router, as one page with two views — and which view you get is the server's answer, not the page's guess.

  • NewA tech sees the queue — every company's tickets and the internal notes. A client sees their own tickets and the conversation on them, with the notes filtered out in the query rather than hidden on screen. Both flags ride on every response, so the page is never holding a ticket it doesn't know the rules for.
  • NewColumn filters on the headings worth asking about: status and priority as multi-selects, title, company, opened by and assignee as text. Draft and apply, like the item grids, with a strip showing what's on so a short list never reads as an empty queue.
  • NewLive updates. An open ticket asks every five seconds and the thread follows; the queue offers instead of interrupting — Refresh lights up and reads "new activity", and pressing it applies the list already fetched, which costs no call.
  • NewFile a ticket with the screenshot already on it. The ticket is created, the files upload one after another, and the pane opens last, so the files are on the ticket when it appears.
  • UpdateThe pane reads as a card: a navy header with the number, the title and the two pills that answer "where is this up to" before anything else, with the meta and controls on their own ground beneath.
  • UpdateOpen to owners and up rather than level 9 alone. Both capability flags trip at level 8, so a level-7 account gets the client view from the server — the only way to prove the internal-note filter, which no non-tech has ever exercised.
  • FixA screenshot now shows up without reopening the ticket. Attaching a file writes no comment, so there was no id for the poll's cursor to move past, and the one thing a tech most wants to see was the one thing that never arrived.
  • FixThe queue stopped announcing news on a queue nobody had touched, and the banner that repeated what the Refresh button already says is gone.
  • RemovedThe mock's Configs, Templates, API keys and Ticket docs tabs, which had no tables behind them, and the client-side guess at who counted as elevated.

A margin collapse that never happened

Vendors and Sub Dept Margins · dev version only

Reported from 005 BT Glennville, 9/16–9/22: H&W Farms showed 24.00% this week, 24.00% last week, and a 24-point collapse — graded Critical.

  • FixBoth weeks really did run at 24%. The vendor sold on Tuesday and Saturday this week and only on Friday last week, and comparisons are day-matched so a part week isn't measured against a full one — leaving one shared day, on which this week sold nothing. A margin delta now needs sales on both sides; with either side empty the row is ungraded rather than Critical.
  • UpdateA day with nothing sold reads as a dash rather than 0.00%, which had looked like a day sold at cost. The detail panel works the same figures a second time, so it got the same rule.
  • FixSub Dept Margins had the same flaw, guarding the prior side and not this one: a department selling on different days each week could match on a day it didn't sell and report a collapse.
  • InternalProd is untouched and still shows the figure clients have been reading. It needs approving on dev first.
